# Veyra CI Reliability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the merged Veyra CI system produce reliable PR signals by fixing benchmark report handling, staging Tauri resources, and removing obsolete Electron checks from the required validation path.

**Architecture:** Keep one fast code-validation workflow, one Tauri validation workflow, and one SemanticPOSS benchmark workflow. Benchmark execution remains authoritative; report generation is diagnostic and must not hide the original failure. Tauri validation will stage the same relocatable backend used by release packaging before invoking the Tauri build.

**Tech Stack:** GitHub Actions YAML, Python 3.12, Python `unittest`, Tauri 2/Rust, existing backend staging scripts.

**Spec:** `AGENTS.md`, `docs/desktop-electron-audit.md`, and the CI findings from PRs #30 and #31.

## Global Constraints

- Do not change mapper/perception behavior.
- Do not commit datasets, model weights, or generated benchmark artifacts.
- Preserve real SemanticPOSS execution and checksum verification.
- Keep benchmark correctness failures hard failures.
- Do not retain Electron as a required PR validation path after Tauri validation is wired.
- Verify workflow YAML, benchmark tests, and local builds before commit.
